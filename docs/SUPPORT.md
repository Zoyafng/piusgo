# 在线客服使用与运行说明

## 入口

- 用户端：商城右侧“在线客服”，首次点击后才加载聊天模块。
- 客服端：`/support`，现有管理员可以直接使用；后台侧栏也有入口。
- 需要独立客服账号时，先正常注册并确认该账号属于预期人员，再由维护者执行：

```sh
.venv/bin/python -m backend.admin_access USER_EMAIL --role support
```

该命令不创建账号、不设置共享密码，会清除该账号已有登录会话。重新登录后使用工作台。未给任何现有账号自动授予新权限。撤销角色使用原有 `--revoke` 参数。

## 接待流程

1. 客服进入工作台，点击“开始接待”。
2. 用户留言后进入待接待队列。只打开常见问题而未发消息的空会话不进入队列。
3. 客服选择会话接待，发送文字、截图或快捷回复。
4. 可以转接到其他已启用的客服。转接提交后，原客服无法再读取或回复该会话。
5. 用户可从自己当前身份的订单中选择关联。客服只看到订单摘要，不展示卡密和账户余额；游客订单号仅显示尾号，避免泄露查单凭据。
6. 已付款且已关联订单的会话可以转工单；同一会话重试不会重复创建。工单后续处理仍使用现有工单模块。
7. 结束会话后，新用户消息会重新排队。不会自动把离线客服的会话转给其他人；管理员可显式转接。

在线标记依据 45 秒有效期的客服心跳，工作台每 20 秒刷新心跳。没有活跃客服时显示离线，并允许留言。该标记不承诺即时人工响应。

## 数据与身份

- 会员会话按服务端登录用户 ID 隔离；游客会话按 HttpOnly 游客 cookie 隔离。填写邮箱不能绑定他人的会话或订单。
- 游客联系邮箱明确标记未验证。会员邮箱从服务端读取，不能通过客服接口修改。
- 登录、退出、改密会广播无敏感内容的身份变更事件，聊天组件清空旧身份状态；另有焦点检查和定时身份校验。
- 清除浏览器 cookie 会失去游客会话的自动访问能力。本版不提供凭邮箱恢复游客聊天功能。
- 消息不存入浏览器 localStorage。草稿仅在当前页面内存中保存，未确认发送的草稿不承诺跨刷新恢复。
- 消息发送者、会话归属、客服权限及接待归属都由后端校验，不接受客户端指定发送者身份。

## 可靠性设计

- HTTP 发送消息，提交事务后返回确认；每条消息有客户端幂等标识，重复请求返回同一条记录。
- 会话内消息采用递增序号；SSE 与轮询都按序号补拉，前端合并去重。
- 首次加载最近 100 条消息，支持加载更早历史。SSE 断线通过 Last-Event-ID / 游标恢复。
- SSE 每次最长 20 秒，会自动续连；每 2 秒查询持久化消息和会话状态。不可用时前端退回轮询。连接期间不占用长时间数据库事务。
- 当前以 PostgreSQL 作为消息和状态来源，没有引入 Redis 内存广播，跨进程重启不丢已提交记录。高并发时可在保留此持久化补拉机制的前提下增加 Redis 通知层。
- 每身份最多 2 条 SSE，当前数据库 schema 总计最多 60 条。租期与过期清理避免断线永久占位。这是初始保护上限，不代表已完成 60 用户并发容量验收。
- 接待、转接、消息序号与幂等使用数据库事务/行锁；只增消息权限阻止运行账号直接修改或删除历史消息。
- 已读位置只能递增且不能超过会话末尾；已发送表示服务端已保存，已读表示对方客户端上报阅读。

## 截图

- PNG/JPEG/WebP，原始文件最多 1 MB，边长最多 4096，最多 1200 万像素。
- 服务端验证真实格式、解码后转 WebP，去除原始 EXIF 等元数据。SVG、其他格式及无效图片拒绝。
- 同一会话附件累计最多 20 MB；另有上传频率限制。
- 保存到 `SUPPORT_ATTACHMENT_DIR`，本地默认 `backend/data/support-attachments`。目录 0700、文件 0600，下载需重新验证会话权限；未发送的附件只能上传者预览。
- 存在数据库中但从未发出的附件，可在超过 24 小时后运行以下维护命令清理。已发送附件和消息不被清理：

```sh
.venv/bin/python -m backend.support_cleanup
```

本版未自动安排清理任务，也未设置已发送聊天记录的删除周期。留存周期、脱敏与删除流程需结合实际运营要求配置。

## 部署

迁移版本：`0007`；迁移前本地备份：`backend/backups/pre-support-0007.dump`。

```sh
npm run db:migrate
npm run dev
```

Docker 配置增加独立 `support_attachments` 私有持久卷，Caddy 关闭代理响应缓冲以支持 SSE。备份脚本现在同时打包商品图片与客服附件，生成 `-files.tar.gz`；旧 `-images.tar.gz` 不含客服附件。恢复时必须保持数据库与附件备份配对。

目前面向单机部署。多主机部署需共享私有对象存储，而不是各自使用本地附件目录。公网启用前仍需验证可信代理 IP、限流实际行为、TLS、备份恢复、留存策略与并发容量。没有自动部署到云端。
