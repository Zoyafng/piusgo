# AI模享 / PiusGo

前后端分离的数字服务商城，本地演示版本。登录页与商城首页依据用户提供的截图及公开样式实现；商品详情、个人中心等沿用同一视觉风格，尚未与参考站登录后页面逐项核对。

## 启动

需要 Node.js 20.9+、Python 3.12+ 和 Docker。后端使用 PostgreSQL 17、SQLAlchemy 2 连接池和 Alembic 迁移。

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock
npm --prefix frontend ci
npm run db:setup
npm run dev
```

- 前端：http://127.0.0.1:3000
- 登录：http://127.0.0.1:3000/login
- 后端：http://127.0.0.1:8000
- OpenAPI：http://127.0.0.1:8000/docs

前端、后端和邮件工作进程独立运行，npm run dev 会一起启动。Next.js 通过 `/api/*` 将浏览器请求转发至独立 FastAPI 服务，浏览器使用同源 HttpOnly Cookie。商品页与首页通过服务端获取 API 数据进行 HTML 渲染，业务和数据库逻辑不放在前端。

## 已实现的演示流程

- 邮箱注册、登录图形验证码、邮箱找回密码、注销和会话失效。
- 商品分类、搜索、详情页、商品规格、购买数量和优惠券选择。登录用户的接收邮箱由后端从会话确定。
- 创建订单、查单、取消待付款订单、模拟支付宝、模拟微信以及演示余额支付。
- 支付后生成明确标注的演示卡密；重复支付不重复扣余额或库存。
- 个人中心：余额、订单数、可用优惠券、充值记录。
- 每人限领一次新人优惠券：满 100 元减 10 元。
- 模拟充值：100 赠 5、300 赠 20、500 赠 50，按整数分记账。
- 工单创建、查看以及订单归属校验。
- 后台上架的商品免费抽奖：服务端使用安全随机数，10% 概率；同一账号每件商品每日一次，以 UTC 日界线计。中奖直接扣减所选规格库存，生成零元中奖订单和演示交付。

所有商品与优惠为 mock 配置。商品种子数据来自参考站公开快照；库存与价格在本地数据库中独立变化。初始种子数据包含 24 件促销商品；首页卡片完全来自后台上架的商品，包含新建的促销与抽奖商品。真实账号密码未写入代码、种子数据或测试。

## 手动验证

1. 打开 `/login`，切到注册，填写邮箱、密码和确认密码，无需验证码。
2. 密码至少 8 位且两次输入一致。注册成功后自动进入个人中心。找回密码仍使用邮箱验证码（本地 mock 显示）。
3. 进入新人优惠，领取一次优惠券；再次进入确认不能重复领取。
4. 打开商城并选购商品，填写接收信息、数量和优惠券，提交订单。
5. 在查订单页选择模拟支付，查看演示交付内容。
6. 在充值优惠中模拟充值，另建订单使用余额支付。
7. 在工单中心关联自己的订单并提交工单。
8. 退出账号后重新登录，确认订单与工单仍在；注册另一个账号，确认无法查看前一个账号的数据。

## 配置和部署边界

前端示例见 `frontend/.env.example`，后端见 `backend/.env.example`。后端环境变量需由进程环境注入，不自动读取 `.env` 文件。

- `API_URL`：前端服务端连接的后端地址。
- `SITE_URL`：自己的正式域名，用于 canonical、Open Graph 和 sitemap。
- `INDEX_SITE`：默认关闭抓取。正式商品与真实服务配置完成后可开启。
- `MOCK_MODE`：本地默认 true。生产模式不允许与 mock 同时启动。
- `APP_ENV=production`：开启 Secure Cookie，必须通过 HTTPS 访问。
- `WEB_ORIGIN`：浏览器前端源，后端检查写操作 Origin，需与部署域名一致。
- `DATABASE_URL`：PostgreSQL 应用连接地址，使用非管理员 piusgo_app 角色。
- `MIGRATION_DATABASE_URL`：仅数据库迁移、导入及测试建表使用的 owner 地址。
- 本地 `.env.postgres` 由 `npm run db:setup` 自动生成，权限 0600，已加入忽略文件；生产必须由环境/密钥服务注入。
- `CAPTCHA_FONT`：可选的服务器字体路径；Linux 可配置 DejaVuSans-Bold.ttf。

正式发布前尚需验证真实 SMTP 配置、接入支付网关签名回调、真实供货/交付及后台运营部署。关闭 mock 后，未配置的邮件、支付、充值和抽奖接口返回明确的未开放错误，不会伪装成功。代理及推广佣金当前只有说明页面，不含结算或提现。

数据库使用事务、订单行锁及幂等操作的事务级锁保证支付、规格库存和优惠券更新原子性。应用账号无建表/超级用户权限，不可更新或删除审计事件。当前面向本地演示，并非已完成生产压测、风控或运维配置的线上系统。

## PostgreSQL 管理与本次数据迁移

- PostgreSQL 仅监听 `127.0.0.1:55432`，使用本项目独立 Docker 数据卷。
- `npm run db:setup`：首次安装，生成随机凭据、启动数据库、创建受限应用角色、迁移并填充 mock 商品；可重复运行。
- `npm run db:up` / `npm run db:stop`：启动/停止数据库，保留数据卷。
- `npm run db:migrate`：应用 Alembic 迁移并更新运行账号权限；`npm run db:check`：检查模型与迁移一致性。
- 应用启动不会自动建表或执行 DDL。生产迁移应作为单独部署步骤执行。
- 原 SQLite 文件和 `backend/backups/pre-postgres.sqlite3` 保留。本次导入在单一事务中逐字段比对所有表，统计在 `security/postgres-migration-counts.json`。
- 一次性导入工具：`.venv/bin/python -m backend.import_sqlite /absolute/path/snapshot.sqlite3`。必须先迁移表结构且目标业务表为空；工具拒绝覆盖已有数据，失败时整体回滚。
- 导入后产生的新数据只写 PostgreSQL；旧 SQLite 不是实时副本，不能直接切回而忽略新增数据。
- 自动备份、恢复演练与生产容量测试仍待部署阶段完成。

## 游客订单、支付弹窗与工单（迁移 0002）

- 未登录用户填写邮箱即可下单；登录用户自动使用账户邮箱。游客不能使用余额和会员优惠券。
- `/orders` 无需登录，有我的订单、游客订单和缓存查单入口。会员订单验证本人会话。游客单号包含 192 位随机值，完整单号本身是查单凭据，请按秘密保存。
- 浏览器最多缓存 20 个订单号，不缓存卡密或邮箱。游客工单使用 HttpOnly 浏览器身份 cookie；清除 cookie 后不再自动显示原浏览器工单。
- 点击购买后展示二维码弹窗和订单已创建页面。点击「模拟付款成功」后，页面轮询并显示卡密、邮件状态和使用指南。二维码不是收款链接，不能用于真实支付。
- 订单超过 30 分钟会自动关闭。支付、卡密和邮件任务在一个数据库事务中保存；重复支付不重复扣库存或生成交付。
- 邮件工作进程默认 MAIL_MODE=mock，将 .eml 文件保存在 backend/data/mail/，不向外部邮箱发送。配置 MAIL_MODE=smtp、SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、SMTP_FROM 后可发送真实交付邮件；465 使用 TLS，其他端口强制 STARTTLS。当前未验证真实 SMTP 外发。
- 邮件失败最多自动重试 5 次，不撤销已完成付款。SMTP 成功但确认丢失等情况下收件端仍可能收到重复邮件，固定 Message-ID 不等于端到端恰好投递一次。
- 工单记录支持按标题/工单号搜索、状态过滤、后端分页与跳页。创建时必须选择已付款订单、优先级、标题和详情，每个订单一张工单。
- 历史已付款订单不补发旧邮件，仍可查看卡密。
- 迁移前备份：backend/backups/pre-guest-checkout-0002.dump。已有游客订单或邮件记录时会拒绝直接降级，避免数据丢失。
- 本地访问日志关闭，响应使用 no-referrer，减少游客单号泄漏。正式反向代理也必须脱敏订单凭据。

## 个人中心更新（迁移 0003）

- 首页展示个人资料与最近 5 笔购买记录，订单支持跳转到对应详情。
- 个人资料支持修改昵称、联系电话；登录邮箱单独只读显示。
- 修改密码必须验证当前密码，保存后撤销全部会话；并发登录会重新核对凭据，避免旧密码验证结果在改密后建立新会话。
- 记录最近和上次成功登录的时间及网络对端 IP。旧记录未知时显示空值，不回填虚构数据。本地代理环境通常显示 127.0.0.1。

- 赠送规则沿用已有 mock 梯度：满 100 赠 5、满 300 赠 20、满 500 赠 50，按最高满足的一档计算，不叠加；实际金额与赠送由后端校验计算。
- 充值记录仍保存在数据库，只是个人中心首页展示改为最近购买；充值方式也会入账记录。
- 迁移前备份：backend/backups/pre-account-update-0003.dump。

## 后台管理（迁移 0004）

入口：<http://127.0.0.1:3000/admin>。使用商城已有账号登录；普通会员无法读取或操作后台接口。管理员个人中心会显示「管理后台」入口。

先在商城注册自己的账号，然后在项目根目录显式授予权限（将邮箱替换为实际注册邮箱）：

```sh
.venv/bin/python -m backend.admin_access your-email@example.com
```

该命令撤销此账号旧会话，需要重新登录。没有内置管理员密码，不会自动提升第一个注册账号。撤销资格使用同一命令加 `--revoke`。

- **概览**：用户数、订单数、已付款成交金额、商品数、近期成交趋势，以及待付款、工单、失败邮件和低库存提醒。
- **用户**：分页搜索、资料/余额/登录记录详情、修改昵称与电话、启用或禁用。禁用立即撤销全部会话，不能在后台禁用管理员。
- **订单**：会员与游客订单、状态筛选、交付详情、关闭待付款订单。已付款订单不可强制回退，不提供虚构退款或人工标记支付成功。
- **商品**：已有商品名称、分类归属、图片、标签、角标、上下架、规格名称/价格/库存。商品展示价取最低规格价，库存为规格合计；保存时校验版本，避免覆盖并发付款或中奖后的库存。下架阻止新建订单，已有待付款订单仍可完成原交易。现已支持新增商品和增删规格，分类定义仍使用现有配置。
- **工单**：搜索、状态筛选、优先级调整、最新客服回复与处理状态；回复同步到会员或游客原有工单中心。当前保存一条最新客服回复，不含多轮聊天记录或用户追问。
- **优惠券**：查看归属、面额、门槛和使用状态；停用未使用券。沿用现有 `used` 字段，界面标注「已使用 / 停用」，可通过操作日志区分停用事件。
- **充值、抽奖、日志**：分页查看原始记录；不直接改写余额、中奖结果或历史财务记录。
- **邮件**：投递状态及错误原因，失败邮件可重新排队；排队中、发送中和已发送邮件不可重复手动重试。
- **内容**：编辑公告、教程、代理/推广说明和平台说明的标题、简介、段落，保存到数据库并由前台服务端读取；纯文本渲染，不执行 HTML。

所有后台接口在服务端校验管理员身份，写操作沿用同源/CSRF检查及严格字段白名单，并在同一事务追加审计日志。账号密码哈希、会话令牌和游客浏览器凭据不会通过后台返回。商品之外的更新按最后成功保存的内容生效；尚未提供细分员工角色、多人编辑合并、批量导出、真实支付退款或真实卡密供货后台。

迁移前备份：`backend/backups/pre-admin-0004.dump`。迁移为新增字段与内容表，保留现有业务数据。执行 `npm run db:migrate` 后重启开发服务。44 项隔离 PostgreSQL 集成测试覆盖原购物流程及后台权限、账户禁用、库存冲突、工单回复、内容同步、邮件重试和操作日志。


## 商品发布与前台联动（迁移 0005）

在后台「商品管理」点击「新增商品」，填写后选择「保存并上架」；也可以「保存为下架」。商品类型支持促销商品、抽奖商品，配置名称、图片、标签、分类、角标、到手价、总库存、规格单价/库存和活动优惠券开关。

- 图片可使用现有素材路径、HTTPS URL，或上传最大 1 MB 的 PNG/JPG/WebP。上传端校验真实图像格式与像素数，重新编码为 WebP，存放在 `backend/data/product-images/`；部署时应持久化此目录并纳入备份。`PRODUCT_IMAGE_DIR` 可覆盖存储目录。
- 单规格可直接填写到手价和总库存；多规格的到手价取最低单价，总库存为规格库存合计。后台和服务端都校验一致性，前台多规格显示「起」，实际下单使用所选规格价格。
- 规格可以新增或移除。被历史订单引用的规格保留记录并停止新购，不更改旧订单的规格快照。存在待付款订单时，禁止移除对应规格或切换商品类型。
- 上架商品立即进入公共商品接口，前台重新进入或刷新即可看到；下架后不再展示，阻止新单和新抽奖。已创建待付款单继续使用创建时的价格与优惠快照，支付仍检查实时库存。
- 关闭活动优惠券后，前台不显示可用券，下单接口也拒绝强行提交优惠券；并不取消此前已经创建的优惠订单。抽奖免费参与，不使用优惠券；该开关在抽奖商品转为促销商品时参与销售校验。
- 抽奖为每账号、每商品、每日一次（UTC），规格共享次数，固定 10% 演示中奖概率。中奖在同一数据库事务中扣 1 件规格/商品库存、创建 `source=lottery` 零元已付款订单、写入演示交付和邮件队列。未中奖不扣库存；并发重试不会重复发奖，交付失败整体回滚。
- 商城首页已移除硬编码的抽奖卡片；`/lottery` 展示后台已上架的抽奖商品。旧的发券式 `/api/lottery/enter` 返回 410，之前发出的历史券仍按原商品范围和当前优惠券规则使用。
- 新增商品支持请求幂等、字段校验和审计；商品保存、下单、付款和抽奖按商品串行协调库存变更。

迁移前备份：`backend/backups/pre-product-publish-0005.dump`。现有商品默认保持上架状态与促销类型，保留价格、库存、用户、订单和管理员权限；不会自动向真实开发商城插入验收商品。44 项测试覆盖发布到前台、规格删除的历史保护、优惠券开关、图片校验、中奖隐私与幂等、最后一件库存并发和交付失败回滚；中奖分支使用隔离数据库中的受控随机值验证，生产代码无强制中奖开关。
