# AI云充 / PiusGo

前后端分离的数字服务商城，本地演示版本。登录页与商城首页依据用户提供的截图及公开样式实现；商品详情、个人中心等沿用同一视觉风格，尚未与参考站登录后页面逐项核对。

## 启动

需要 Node.js 20.9+、Python 3.12+ 和 Docker。后端使用 PostgreSQL 17、SQLAlchemy 2 连接池和 Alembic 迁移。

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock
npm --prefix frontend ci
npm run db:setup
npm run dev
```

- 前端：http://127.0.0.1:3000
- 登录：http://127.0.0.1:3000/login
- 后端：http://127.0.0.1:8000
- OpenAPI：http://127.0.0.1:8000/docs

前端、后端和邮件工作进程独立运行，npm run dev 会一起启动。Next.js 通过 `/api/*` 将浏览器请求转发至独立 FastAPI 服务，浏览器使用同源 HttpOnly Cookie。商品页与首页通过服务端获取 API 数据进行 HTML 渲染，业务和数据库逻辑不放在前端。

## 已实现的演示流程

- 邮箱注册、登录图形验证码、邮箱找回密码、注销和会话失效。
- 商品分类、搜索、详情页、商品规格、购买数量和优惠券选择。登录用户的接收邮箱由后端从会话确定。
- 创建订单、查单、取消待付款订单、模拟支付宝、模拟微信以及演示余额支付。
- 支付后生成明确标注的演示卡密；重复支付不重复扣余额或库存。
- 个人中心：余额、订单数、可用优惠券、充值记录。
- 每人限领一次新人优惠券：满 100 元减 10 元。
- 模拟充值：100 赠 5、300 赠 20、500 赠 50，按整数分记账。
- 工单创建、查看以及订单归属校验。
- 指定商品免费抽奖：服务端使用安全随机数，10% 概率；同一账号每日一次，以 UTC 日界线计。中奖发放限商品 188 使用的 148 元优惠券。

所有商品与优惠为 mock 配置。商品种子数据来自参考站公开快照；库存与价格在本地数据库中独立变化。首页的 24 件商品加 1 个抽奖入口，对应 25 个展示卡片。真实账号密码未写入代码、种子数据或测试。

## 手动验证

1. 打开 `/login`，切到注册，填写邮箱、密码和确认密码，无需验证码。
2. 密码至少 8 位且两次输入一致。注册成功后自动进入个人中心。找回密码仍使用邮箱验证码（本地 mock 显示）。
3. 进入新人优惠，领取一次优惠券；再次进入确认不能重复领取。
4. 打开商城并选购商品，填写接收信息、数量和优惠券，提交订单。
5. 在查订单页选择模拟支付，查看演示交付内容。
6. 在充值优惠中模拟充值，另建订单使用余额支付。
7. 在工单中心关联自己的订单并提交工单。
8. 退出账号后重新登录，确认订单与工单仍在；注册另一个账号，确认无法查看前一个账号的数据。

## 配置和部署边界

前端示例见 `frontend/.env.example`，后端见 `backend/.env.example`。后端环境变量需由进程环境注入，不自动读取 `.env` 文件。

- `API_URL`：前端服务端连接的后端地址。
- `SITE_URL`：自己的正式域名，用于 canonical、Open Graph 和 sitemap。
- `INDEX_SITE`：默认关闭抓取。正式商品与真实服务配置完成后可开启。
- `MOCK_MODE`：本地默认 true。生产模式不允许与 mock 同时启动。
- `APP_ENV=production`：开启 Secure Cookie，必须通过 HTTPS 访问。
- `WEB_ORIGIN`：浏览器前端源，后端检查写操作 Origin，需与部署域名一致。
- `DATABASE_URL`：PostgreSQL 应用连接地址，使用非管理员 piusgo_app 角色。
- `MIGRATION_DATABASE_URL`：仅数据库迁移、导入及测试建表使用的 owner 地址。
- 本地 `.env.postgres` 由 `npm run db:setup` 自动生成，权限 0600，已加入忽略文件；生产必须由环境/密钥服务注入。
- `CAPTCHA_FONT`：可选的服务器字体路径；Linux 可配置 DejaVuSans-Bold.ttf。

正式发布前尚需验证真实 SMTP 配置、接入支付网关签名回调、真实供货/交付和后台管理。关闭 mock 后，未配置的邮件、支付、充值和抽奖接口返回明确的未开放错误，不会伪装成功。代理及推广佣金当前只有说明页面，不含结算或提现。

数据库使用事务、订单行锁及幂等操作的事务级锁保证支付、规格库存和优惠券更新原子性。应用账号无建表/超级用户权限，不可更新或删除审计事件。当前面向本地演示，并非已完成生产压测、风控或运维配置的线上系统。

## PostgreSQL 管理与本次数据迁移

- PostgreSQL 仅监听 `127.0.0.1:55432`，使用本项目独立 Docker 数据卷。
- `npm run db:setup`：首次安装，生成随机凭据、启动数据库、创建受限应用角色、迁移并填充 mock 商品；可重复运行。
- `npm run db:up` / `npm run db:stop`：启动/停止数据库，保留数据卷。
- `npm run db:migrate`：应用 Alembic 迁移并更新运行账号权限；`npm run db:check`：检查模型与迁移一致性。
- 应用启动不会自动建表或执行 DDL。生产迁移应作为单独部署步骤执行。
- 原 SQLite 文件和 `backend/backups/pre-postgres.sqlite3` 保留。本次导入在单一事务中逐字段比对所有表，统计在 `security/postgres-migration-counts.json`。
- 一次性导入工具：`.venv/bin/python -m backend.import_sqlite /absolute/path/snapshot.sqlite3`。必须先迁移表结构且目标业务表为空；工具拒绝覆盖已有数据，失败时整体回滚。
- 导入后产生的新数据只写 PostgreSQL；旧 SQLite 不是实时副本，不能直接切回而忽略新增数据。
- 自动备份、恢复演练与生产容量测试仍待部署阶段完成。

## 游客订单、支付弹窗与工单（迁移 0002）

- 未登录用户填写邮箱即可下单；登录用户自动使用账户邮箱。游客不能使用余额和会员优惠券。
- `/orders` 无需登录，有我的订单、游客订单和缓存查单入口。会员订单验证本人会话。游客单号包含 192 位随机值，完整单号本身是查单凭据，请按秘密保存。
- 浏览器最多缓存 20 个订单号，不缓存卡密或邮箱。游客工单使用 HttpOnly 浏览器身份 cookie；清除 cookie 后不再自动显示原浏览器工单。
- 点击购买后展示二维码弹窗和订单已创建页面。点击「模拟付款成功」后，页面轮询并显示卡密、邮件状态和使用指南。二维码不是收款链接，不能用于真实支付。
- 订单超过 30 分钟会自动关闭。支付、卡密和邮件任务在一个数据库事务中保存；重复支付不重复扣库存或生成交付。
- 邮件工作进程默认 MAIL_MODE=mock，将 .eml 文件保存在 backend/data/mail/，不向外部邮箱发送。配置 MAIL_MODE=smtp、SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、SMTP_FROM 后可发送真实交付邮件；465 使用 TLS，其他端口强制 STARTTLS。当前未验证真实 SMTP 外发。
- 邮件失败最多自动重试 5 次，不撤销已完成付款。SMTP 成功但确认丢失等情况下收件端仍可能收到重复邮件，固定 Message-ID 不等于端到端恰好投递一次。
- 工单记录支持按标题/工单号搜索、状态过滤、后端分页与跳页。创建时必须选择已付款订单、优先级、标题和详情，每个订单一张工单。
- 历史已付款订单不补发旧邮件，仍可查看卡密。
- 迁移前备份：backend/backups/pre-guest-checkout-0002.dump。已有游客订单或邮件记录时会拒绝直接降级，避免数据丢失。
- 本地访问日志关闭，响应使用 no-referrer，减少游客单号泄漏。正式反向代理也必须脱敏订单凭据。
