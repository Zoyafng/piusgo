# 本地演示版安全检查记录

日期：2026-09-07。范围：本次商品规格/支付选择/邮箱归属变更，以及现有账号、订单与资金模拟流程。不构成 ASVS 认证或独立渗透测试。

## 已验证

- 30 项 PostgreSQL 隔离 HTTP 回归测试通过；生产构建、TypeScript 检查通过。
- 前端 npm audit：0 条已知漏洞；后端 pip-audit 对 requirements.lock 扫描：0 条已知漏洞。报告保存在本目录，仅代表扫描时的软件包数据库结果。
- 修复旧 Pillow、Starlette、Click 的已知漏洞依赖，运行环境升级至 Python 3.12.14。全部后端运行依赖固定在 requirements.lock 中。
- 会话由后端校验。订单接收邮箱只从已登录用户记录读取；前端伪造 account 不会更改收件邮箱。
- 规格必须属于该商品；价格、库存、优惠额度由服务端读取，不接受客户端提交价格。
- 写请求限制 JSON、受信 Origin、自定义请求头及 64 KiB 大小。模型拒绝未知字段，校验错误不回显密码等提交值。
- 登录、验证码、下单、付款、充值、工单均有频率限制；验证码有有效期、失败次数及一次性消费检查。
- 参数化 SQL、按用户限制订单和工单访问，密码 PBKDF2-SHA256（随机盐、600000 次），会话令牌随机生成且仅哈希入库。
- 付款使用单个数据库事务：规格库存、商品库存、余额、优惠券、订单状态与支付审计记录共同提交或回滚。
- 同一订单重复/并发付款只扣一次；重复幂等键改变商品/规格/数量/优惠券、充值金额会被拒绝。
- 待付款订单超过 30 分钟不能付款。取消后不能付款。库存失败会回滚余额和优惠券。
- 指定商品抽奖券有服务端商品范围校验；每账号每天一次抽奖。
- mock 付款与充值写入审计事件；生产模式禁止与 MOCK_MODE=true 同时启动。mock 关闭后，未接入的支付/充值服务拒绝处理。

## 上线前尚未完成

- 已接入 PostgreSQL 17 + SQLAlchemy 2 + Alembic，并完成原 SQLite 数据逐字段校验迁移。生产备份恢复演练、负载容量和高可用仍未完成。
- 支付网关、签名回调、商户订单/金额/币种一致性、重放保护、对账、退款及真实交付均尚未接入；目前禁止据此接收真实资金。
- 邮件服务、密钥管理、TLS/反向代理、生产级限流、请求超时、监控告警、日志留存和持久化审计保护仍需部署验证。

- mock 邮箱验证码会在页面显示，只适用于受控的本地环境，不能公开提供找回密码接口的 mock 模式。
- 浏览器点击和视觉回归仍受浏览器控制服务不可用影响；接口测试不替代浏览器或独立安全测试。

## PostgreSQL 切换证据

30 项测试在独立随机 schema 中通过，包含真实并发防超卖、并发建单幂等、数据库非负金额约束和运行角色权限。Alembic check 无待迁移变更。原数据快照保留，导入只允许空库，逐表逐字段校验后提交。应用角色与迁移角色分离，连接池有超时与健康检查，所有 SQL 使用绑定参数。
