# 在线客服安全与可靠性记录

本轮使用已有 Python/FastAPI/PostgreSQL/React 依赖，没有引入第三方聊天 SDK，也没有把会话发送给外部服务。

## 已实现并验证的边界

- 用户/游客身份隔离；邮箱不授予会话或订单权限。
- 客服角色与管理员角色分离。客服仅能读取自己接待的会话；管理员有明确的全局管理范围。
- 并发接待只能一方成功。转接后旧客服无法继续回复；结束后用户新消息重新排队。
- 并发消息重试唯一落库，正文变化复用同一标识返回 409。消息序号与写入同一事务。
- 消息运行角色没有 UPDATE/DELETE 权限，接待、转接、查看、工单关联记录审计。
- 私有截图按会话授权；非法格式、跨会话引用、重复附件引用被拒绝；重新编码后交付。
- 已读位置单调递增，不能越过最大序号；未读数量从服务端查询。
- SSE 连接限额、租期回收、Last-Event-ID 补拉和会话撤销检查。
- 跨后端进程读取持久化历史；断线不依赖丢失的内存事件。
- 关联订单必须属于当前身份。客服只得到金额/状态/商品摘要，不得到卡密、其他客户资料或资金操作接口；游客单号因具有查单凭据作用，只返回尾号。
- 转工单关联已付款订单并保证幂等。

## 证据

完整隔离 PostgreSQL 测试 63 项通过，其中 13 项新增客服测试；TypeScript 与生产构建通过。网站代理的真实 HTTP/SSE 检查确认同源 cookie 可用，事件无需等待连接结束即可收到。未使用真实用户账号或授予真实账号权限来执行联调。

## 尚未验收

浏览器控制服务仍返回 Sky Computer Use service startup request failed，因此本轮没有宣称完成真实浏览器点击、跨标签页交互或像素对比验收。跨标签页清理使用 BroadcastChannel，并保留焦点/定时检查作为补充，但浏览器行为仍需人工或后续自动浏览器验证。

未执行生产压力测试、独立渗透测试或异机恢复演练。60 SSE 的配置上限不是实测容量。当前代理部署沿用不信任转发 IP 的配置，公网前应验证真实 IP 传递与限流，防止多个正常用户共用代理 IP 误触限额。

记录和截图没有额外的应用层静态加密；依赖数据库/文件访问权限及部署存储保护。敏感数据留存与删除策略、远程审计归档仍需运营配置。客服不会自动退款、改余额、标记付款成功或调用 AI 执行交易。
