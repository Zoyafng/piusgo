# AI模享业务与风险检查（2026-09-07）

## 范围与结论

检查后端权限、会话、订单/余额/优惠券、商品规格与库存、抽奖交付、邮件队列、后台写入、前端请求流程及现有部署草稿。执行隔离 PostgreSQL 业务测试、TypeScript、生产构建、前后端依赖漏洞扫描、Alembic 一致性检查。

本轮修复 5 个可重现的逻辑边界，补充 6 个测试方法。已有权限、并发扣库存、支付幂等、跨用户访问、请求篡改等用例仍通过。没有在用户真实业务库中创建订单、付款或抽奖；本地库仅备份并执行订单快照迁移。

这不是渗透测试或生产压测，也没有执行真实 SMTP、支付商户回调或云端部署演练。依赖无已知漏洞不能证明没有业务风险。

### 迁移与历史数据限制

新增迁移 0006：订单 product_name/product_image 快照。迁移前备份位于 `backend/backups/pre-review-0006.dump`。历史订单回填迁移时商品表中的名称和图片；迁移前已发生的改名无法从当前商品表恢复，不能把回填结果当作历史原始名称的证明。新建商品订单和中奖订单均会保存准确的下单快照。

SQLite 导入兼容新字段，旧来源没有快照时保留空值并回退商品表。若未来再次导入旧库，需要明确这项历史展示限制。

## 上线前仍需处理的风险和限制

1. **真实交易链路未接入（上线阻断）**：生产配置关闭 mock 时，支付、充值、抽奖交付返回 503；找回密码的真实邮件仍未接入。已额外启动 production + MOCK_MODE=false 的隔离服务，确认模拟付款/充值/抽奖不能执行，余额和订单状态不变；production + MOCK_MODE=true 启动失败。不能将其当作可收款的完整生产商城。
2. **账号滥用（公开启用福利前处理）**：注册没有验证邮箱控制权；当前每账号每日抽奖的规则无法阻止多账号领券或抽奖。现有 IP 频率限制不能替代邮箱验证、设备/行为限额或业务风控。管理员首次授予权限时也必须确认该注册账号属于预期人员。
3. **反向代理的真实 IP 与限流（部署前验证）**：当前读取 request.client.host，部署草稿使用 Next 代理和 `--no-proxy-headers`，因此多名访客可能共享代理 IP 的限额，正常用户会互相触发 429。需要在部署侧配置可信代理地址和安全的客户端 IP 传递；不能直接相信客户端任意填写的 X-Forwarded-For。没有为消除限流误伤而放开代理信任。
4. **邮件至少一次投递**：本轮只阻止旧 worker 覆盖状态。SMTP 已接收但连接中断/确认丢失时，重试仍可能产生重复邮件；Message-ID 不等于收件系统保证去重。真实 SMTP 的可用性与恢复流程未实测。
5. **安全运维尚无完整验收**：管理员目前是单一角色，没有 MFA、细分授权或操作前后值的审计快照。现有只增审计记录能追踪谁做了何种操作，不能完整恢复修改前数据。部署备份配置需进一步进行实际恢复演练与压力测试。
6. **大数据量与售后能力**：商品目录、个人优惠券/充值明细部分接口仍整批读取；未进行大规模数据压测。工单只保存最新客服回复，没有用户追问、多轮消息记录或真实退款流程。
